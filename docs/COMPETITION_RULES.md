# Solar Filament Segmentation Challenge 2026 — rules that constrain this repository

Sources: the Kaggle competition pages (Overview, Data, Rules, Leaderboard),
the organizers' *Self_Evaluation_Notebook* and host answers in the Discussion
forum, read on **5–6 October 2026**. Re-read the Overview page before the
deadline: the organizers changed the evaluation once already (7 Aug 2026).

Competition: <https://www.kaggle.com/competitions/filament-segmentation-2026>

## 1. Task and data

* Instance segmentation of solar filaments in GONG H-alpha full-disk images.
* Images: 2048 × 2048, 8-bit **grayscale** JPEG (converted from FITS). File
  stem = `YYYYMMDDHHMMSS` + 2-letter site code (e.g. `20150125172714Mh`).
* `train/train_images` + `MAGFiLO_1.0_Annotations_kaggle2026_train.json`
  (COCO style); `test/test_images` (no labels). 888 files, ~751 MB.
  Reported in the forum: 707 training observations, 1,154 annotation records,
  8,199 filaments; 180 test observations.
* One annotation = one filament = one closed polygon (`iscrowd = 0`). The
  categories (`Left`, `Right`, `Unidentifiable`, `Ambiguous`) are chirality
  labels: **irrelevant** for the task, every filament counts.
* `image["id"] = "<annotator batch>-<stem>"`; 296 training observations carry
  2–3 independent annotation sets (`010401-…`, `010402-…`). The test set is
  scored per annotation set in the same way.

## 2. What is forbidden / required for training and inference

* Training labels: **only** the annotations shipped with the competition.
  The public MAGFiLO v1.0 release (Harvard Dataverse, doi:10.7910/DVN/J6JNVK)
  contains the labels of the test observations; using it in any form gets the
  submission disregarded (host, Discussion #729396). This repository never
  downloads it.
* External *unlabelled* data (other GONG frames, magnetograms, SDO/AIA, …) is
  allowed for training / pre-training if public and free. `src/gong.py` only
  downloads recent unlabelled NOAA/SWPC GONG frames for self-supervised
  pre-training.
* Inference: the model must predict **from the supplied test image alone** —
  no neighbouring GONG frame or other observation at inference time (host,
  Discussion #743385). `scripts/infer.py` reads only the test folder.
* Foundational rule 4b: no hand labelling of test data.
* Code and libraries must be OSI-licensed without commercial-use
  restrictions; winners license their code under an OSI licence (this
  repository: Apache-2.0, see `LICENSE`).
* AI assistance is allowed, but prize-eligible participants must be able to
  explain, justify and reproduce every component and **its contribution to
  the final result** (Rules 8.b; host, Discussion #724503) → keep the
  ablations and read `docs/GUIDA_IT.md`.

## 3. Submission file (leaderboard)

* One CSV for the whole test set, header exactly `filament_id,segmentation_rle`.
* One row per predicted filament; `filament_id = <image stem>_<k>` (the suffix
  only makes rows unique; the scorer takes the image id as the text before the
  first `_`).
* `segmentation_rle` = pycocotools compressed RLE **counts** of a 2048 × 2048
  mask; no size, **no quotes**.
* 5 submissions per day; up to 2 final submissions can be selected.
* The scorer rejects files that look not model-generated ("submitted
  predictions are unlikely to be generated by a model", Discussion #741883).

Implemented and tested in `src/submission.py`, `scripts/infer.py`,
`scripts/validate_submission.py`.

## 4. Leaderboard metric — Panoptic Quality (exact semantics)

From the organizers' Self_Evaluation_Notebook (host: "exact implementation of
PQ"):

* the ground truth is grouped by annotator-image entry (`<batch>-<stem>`);
  each entry is compared with **all** predictions of its image;
* hit = IoU **> 0.5** (strict); every hit is a TP and adds its IoU; a
  prediction without hits is an FP; a GT filament without hits is an FN;
* counts are summed over all entries, then
  `PQ = Σ IoU(TP) / (|TP| + 0.5|FP| + 0.5|FN|)` — **micro**, not a mean of
  per-image PQ;
* only images present in the ground truth are scored.

Consequences used here:

* an observation with 3 annotators weighs 3 times; a filament drawn by only
  one of three annotators is a TP for one entry and an FP for the two others;
* predictions must be pairwise **disjoint** (panoptic). Overlapping duplicates
  would be counted twice by the notebook code, but exploiting that is "hacking
  the system" — the organizers check for it;
* adding an instance whose probability of being matched is `p` with expected
  IoU `u` raises the global PQ iff `p · u > PQ / 2` → low-confidence
  instances must be dropped (`inference.min_instance_score`).

Implemented in `src/pq_official.py` (exact, on RLEs).
`tests/test_official_parity.py` checks it against an independent dense
re-implementation (`tests/reference_pq_dense.py`) on random multi-annotator
scenes, and `tools/verify_against_official_notebook.py` runs the organizers'
own notebook functions (not redistributed here) on the same inputs: identical
PQ on every scene tested (10 Oct 2026, notebook version 6).

## 5. Final evaluation (what decides the prizes)

The public leaderboard is only a preliminary filter. Judging rubric:

* **Quantitative, 70 %**: PQ; distribution of Dice scores; distribution of IoU
  scores; distribution of one-to-many / many-to-one relations between GT and
  predictions; end-to-end computational efficiency.
* **Qualitative, 30 %**: description of the whole pipeline (pre-processing to
  prediction, architecture); apparent morphology of the predicted
  segmentations on the H-alpha images; code quality (modularity,
  documentation).

Deliverables, through the organizers' Google form, by **15 November 2026**:

1. 4-page technical report (organizers' Overleaf template), single PDF;
2. public Git repository readable without any permission request, kept public
   at least until the winners are announced (30 Nov 2026), with a
   `requirements.txt` listing **every** package with its **version**, and a
   Jupyter notebook illustrating the entire pipeline; the committee must not
   need any additional file to reproduce the submitted predictions (the
   weights must be downloadable from a link in the repository, or reproducible
   by its training code).

Host guidance on scores (forum, Sept–Oct 2026): honest solutions are in the
0.35–0.50 PQ range; "any PQ score of greater than 0.35 is of great value",
"we take a score of 0.41 very seriously". The 0.55+ cluster on the public
leaderboard is attributed to the public-label leak.

## 6. Prize split

Up to $3,000 for the top 3 teams, proportional to `score²` of the rubric
score. Team size ≤ 5.
